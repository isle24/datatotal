# NAS 控制台 UI 与交互改版

## 设计依据

参考 [Taste Skill](https://github.com/Leonxlnx/taste-skill) 的现状审查、排版和间距原则，以及 [Impeccable Operate](https://github.com/pbakaus/impeccable/blob/main/skill/reference/operate.md) 的产品界面、状态、原生控件和清晰文案原则。Taste v2 默认面向营销页面，本项目保留 Vue 与现有主导航，不套用营销布局或替换框架。

使用场景为中文 NAS 日常监控。默认采用专业、克制的控制台：数据和状态优先，中等密度，保留明暗主题，离线可用字体，无外部图片/字体请求与装饰动画。设置分区保留模型草稿，不因切换页面或保存别的分区丢失修改。

## 实施计划

- [ ] 可搜索的容器选择器：单选 radio、多选 checkbox、选择结果摘要、选择/清除当前搜索结果、保留暂时不可见的已选目标、加载/错误/重试。不再手填名称/ID。
- [ ] 设置功能区：常用设置、流量告警、容器保护、通知渠道、AI 配置、维护与高级；明确当前保存范围、未保存状态与失败反馈。
- [ ] 草稿保护：刷新、页面切换及保存别的分区不覆盖未保存修改；保存失败保持输入；重复保存阻止；显式放弃才重新加载。
- [ ] 通知渠道明确三种模式：全部启用、指定渠道、不通知。兼容原空列表代表全部启用的配置；指定但未选不默认为全部。
- [ ] 可读表单：条件逻辑中文、指标和时间单位明确；移除模型选择重复输入；Docker 服务类型改为列表；通知模板/启动参数作为进阶项；测试按钮明确是否保存并发送。
- [ ] 其他交互：连接筛选完全重置及标签；Docker/网卡/进程的加载、空数据和无匹配区分；自定义日期验证后应用；导航编辑原生 dialog 与草稿保护。
- [ ] 独立视觉样式：统一层级、表格、按钮、字体、间距和响应式，去掉装饰网格/渐变和过多卡片。
- [ ] 单元回归、前端两种构建、桌面/手机及明暗主题浏览器验证，检查键盘与实际保存回读。
- [ ] 延续用户已授权的发布流程：新版 Docker Hub 多架构镜像，原 NAS Compose 备份与更新，验证原设置/历史保留。

组件、视觉样式、导航编辑器分别由不同文件负责；不改容器保护不限重启次数、每日统计口径和原规则身份。验证使用隔离数据与模拟通知，不手动触发 NAS 容器动作或真实通知作为测试。

## 手风琴卡片（系统温度、风扇与 Docker）

- Docker 容器列表、监控规则状态、系统温度分组和风扇卡片统一为同一种折叠卡片：收起时显示名称、来源和关键读数，点击标题展开明细，同一堆叠可同时展开多张，展开体带一次性进入动画。
- 系统页温度按传感器组展示：标题显示分组名、原始传感器名、传感器数量和最高温度；展开后每行显示标签、`上限`、温度条和读数，颜色跟随服务端返回的 `level`（`ok` / `warning` / `critical`）。
- 温度条按 `critical`、`high` 中较小者归一；hwmon 的 `65261.85` 这类哨兵上限会被忽略并回退到 100°C，避免所有读数都贴在最左侧。
- 风扇卡片收起时显示名称、运行状态和转速，展开后显示传感器标识与相对最高转速的比例条。
- 卡片顺序保持服务端返回的稳定顺序，仅在首次加载时默认展开最热的一组，避免 5 秒轮询下卡片因温度波动互相换位。
- 纯函数集中在 `front-end/src/utils/system-cards.js`，回归用例在 `front-end/tests/system-accordion.test.mjs` 与 `front-end/ui-contract` 相关断言。

## 主色改为浅蓝

原主题的主色（`--accent`）是深绿 `#176a58`，中性色也偏绿（`--bg: #f4f3ef`、`--line: #d7ded8`、深色主题 `#171d1b/#212925`），整体偏绿。现在：

- 浅色主题主色 `--accent: #2578b8`、悬浮 `#1f689f`、浅底 `#e6f1fa`；深色主题 `--accent: #7db8e8`、浅底 `#1f3548`。
- 中性色改为冷灰蓝：浅色 `--bg: #f3f5f8`、`--panel: #ffffff`、`--line: #d9e0e9`、侧边栏 `#222b35`；深色 `--bg: #141a21`、`--panel: #1e2732`、`--line: #34404e`。
- `--cyan`、`--teal`、`--blue` 跟随主色；`--green` 只保留给状态语义（运行中、成功反馈、活跃指示）。
- 温度读数：正常值改为浅蓝底片（`--accent` 12% 混合），`warning`/`critical` 保持橙/红；温度条和风扇相对转速条也改为主色。桌面端 `--ds-accent` 同步为 `#2578b8` / `#7db8e8`。
- 回归在 `front-end/tests/accelerator-panel.test.mjs` 中断言浅色/深色主色值、中性色不再偏绿，以及异常状态仍使用橙/红。

## GPU 与 NPU 利用率

- 系统页新增「GPU 与 NPU」手风琴卡片：收起时显示设备名、驱动/节点、空闲或使用中、利用率；展开后核显按引擎列出 Render/3D、Video、Video Enhance、Blitter、Compute 的占比条，并显示驱动、核心频率、空闲驻留（RC6）。
- NPU 卡片展开后显示驱动、当前/最高频率、常驻显存、电源状态、调度模式和累计忙碌时间。
- 采集实现见 `server/services/accelerator_stats.py`：i915 走 PMU（`perf_event_open`），NPU 走 `npu_busy_time_us`，两者都是累计计数，因此用后台线程每 2 秒采样一次求差值，接口不做阻塞采样；硬件「信息」区的 GPU/NPU 行同步显示利用率。
- 读不到计数器时给出可执行的原因（缺 PMU、缺权限、缺设备节点、内核版本），不再统一显示“未暴露利用率”。
