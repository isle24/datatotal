# AI 中心与数据大屏设计

## 背景

NAS Traffic Lens 已经具备实时公网流量、历史统计、Docker、监控规则和通知渠道。随着设置项增加，首页、监控配置和分析入口需要更清晰的分工，同时避免把 AI 请求加入持续采集路径，造成额外负载或敏感数据泄露。

## 目标

- 首页第一屏直接呈现公网速率、上下行方向、公网累计、公网连接数、采集接口和刷新状态。
- 监控中心只呈现运行状态；规则、容器保护、通知渠道和运行参数统一在设置页编辑。
- 用纵向手风琴卡片组织规则、渠道和 Docker 容器，默认折叠，展开后才显示细节或编辑器。
- 增加 AI 设置和 AI 中心，支持 OpenAI 兼容接口、快捷分析和连续对话。
- 保持实时采集和 Docker 按需请求的低负载约束，并兼容未配置 AI、旧 SQLite 和测试中的不完整 collector。

## 交互设计

### 导航与页面

左侧导航包含“监控中心”“设置”“AI 中心”，首页仍是默认入口。顶部提供浅色/暗黑图标切换、刷新、设置和退出登录按钮。首页与 AI 中心使用深色数据大屏视觉，但表格、表单和系统页面继续遵循现有卡片系统，确保移动端可读。

监控中心显示规则、容器保护和通知渠道的启用状态，每个状态卡默认折叠；点击“配置”进入设置页。设置页承载运行参数、AI 配置、监控规则、容器保护和通知渠道，每个编辑卡默认折叠，新增操作追加独立卡片。

### AI 设置

设置字段为启用开关、OpenAI 兼容 Base URL、API Key、模型、请求超时、最大输出 Token 和系统提示词。Base URL 只接受 HTTP/HTTPS，API Key 保存后只返回掩码；空值或掩码值提交时保留数据库中原 Key。未配置时，AI 中心显示明确的设置入口而不阻断其他页面。

### AI 分析与对话

首页、历史和监控中心的“AI 分析”按钮发送有限问题并跳转 AI 中心；AI 中心保留当前浏览器会话内的问答消息。后端每次请求即时生成有上限的聚合上下文，包含当前概览、日/周/月/年历史、30 秒进程前十、最多 50 个 Docker 容器摘要、系统状态、监控规则和最近 20 条告警。完整连接明细、API Key 和原始包不发送给 AI。

AI 请求使用 OpenAI-compatible `POST /chat/completions`，只在用户动作触发时执行，使用独立线程避免阻塞 FastAPI 事件循环，也不进入采集线程。响应体限制为 2 MiB，回答限制为 20,000 字符；服务错误返回用户可读信息，不泄露 Authorization header。

## 后端边界

- `server/services/ai.py` 负责默认值、输入规范化、掩码和 HTTP 客户端，不依赖采集器。
- `TrafficCollector.ai_context()` 负责构造有限聚合摘要。
- `TrafficCollector.ai_analyze()` 和 `TrafficCollector.ai_chat()` 负责组装消息并调用 AI 服务。
- `GET/POST /api/settings/ai` 负责读取和保存公开配置。
- `POST /api/ai/analyze` 与 `POST /api/ai/chat` 是显式操作接口；未启用 AI 返回结构化配置提示。

## 兼容性与性能

- `ai_settings` 在 SQLite 中按设置项保存；首次启动写入代码默认值。
- `get_settings()` 对缺少 `ai_settings` 属性的测试实例使用默认值，避免旧测试和迁移路径报错。
- Docker AI 摘要使用轻量列表返回的 `portCount`，不会为了统计端口数重新请求每个容器详情。
- Docker stats 仍只在容器卡片展开并点击显示占用后请求；页面离开时停止刷新。
- AI 未配置时不创建后台任务、不启动定时器、不访问外部网络。

## 验收标准

1. 前端构建成功，桌面和 390px 移动端无明显重叠、横向溢出或不可读按钮。
2. AI 设置规范化、API Key 掩码、旧 Key 保留和 Docker 端口摘要均有测试覆盖。
3. 未配置 AI 时两个 AI 接口返回 `ok: false` 和明确提示，不返回 500。
4. Python、Go（如环境可用）和前端测试通过，Dockerfile 可分别构建 amd64 与 arm64。
5. README 与 `doc/README.md` 只使用示例密码 `123456`，不包含真实凭据。
